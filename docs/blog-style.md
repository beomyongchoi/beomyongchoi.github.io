# 블로그 하우스 스타일 (글·차트·인터랙션)

이 사이트 블로그 글을 쓰거나 고칠 때 지키는 규칙. 근거는 KaiCore AEO 콘텐츠 빌더에서
학습한 문장 규칙(`kaicore/aeo/src/pipeline/_prompt_style.py`, `body_writer.py`)과
imweb 블로그(imweb.me/blog?idx=482) 문장 구조.

## 1. 문장 스타일 (사람이 쓴 톤 — AI 만연체 금지)

- **한 문장 = 한 메시지.** 50~60자 넘으면 마침표로 자른다.
- 콤마로 절을 잇지 말 것. `~하여, ~된, ~기반의, ~하는 …입니다` 패턴 금지 → 짧은 단정문으로 분리.
- **능동태·현재형 단정.** 명사화 지양(`대응하여`→`대응해`, `성과를 내는`→`성과를 낸다`).
- 과잉 수식어 빼기(`가시적인/고품질/압도적인/혁신적인/획기적인` 등).
- 자기소개형 마무리(`~하는 B2B 솔루션입니다`) 대신 동작·결과로 끝낸다.
- 팩트(수치·고유명사·인과)는 유지. 정보를 빼는 게 아니라 문장만 쪼갠다.
- AI틱/클릭베이트/사족 금지(`충격적인`, `시한폭탄`, `다음 장(章)`, `돌아보면 ~라고 느낍니다`).

## 2. 구조

- **Answer-first.** 도입부(또는 상단 콜아웃) 3문장 안에 핵심 결론을 먼저 제시. imweb의 "결론부터 말하면"과 같은 원리.
- 소제목은 `##`/`###`. 번호 + 훅(`1. 신뢰의 역설 — 안 믿으면서 그대로 배포한다`). 질문형도 좋음(`무엇부터 해야 할까요?`).
- **한 문단 2~3문장(120자 이내).** 벽 텍스트 금지. 문단 사이 여백 넉넉히.
- **핵심 강조**: 용어·수치·브랜드명은 `**볼드**`, 문단당 1~2개(남발 금지).
- **콜아웃**: 주의·팁·요약은 박스로 뺀다(섹션당 최대 1개). `BilingualArticle`의 `callout` 블록 타입 + `tone`.
  - **아이콘 규칙(중요): 콜아웃 하나에 아이콘 딱 하나.** tone별 고정: `📌` tldr(결론부터/요약) · `⚠️` warn(주의) · `💡` tip(팁).
  - 아이콘은 텍스트에 인라인으로 넣지 말 것 → `tone` → `data-icon` → CSS `::before`로 렌더(언어 토글 시 innerHTML 교체돼도 아이콘 보존). 이모지 남발 금지.
- **목록**: 3개 이상 나열은 문단이 아니라 불릿(`-`).
- 톤: 존댓말 대화체. 독자에게 말 건다. 본인 관점(백엔드·AI 엔지니어)은 과하지 않게 한 줄.

## 3. 팩트체크

- 사용자 이름으로 나가는 글이라 통계·수치는 반드시 WebSearch로 1차 출처 확인 + 실제 URL을 단다.
- 초안에 틀린 수치가 있으면 정정(예: "자격증명 노출 2배" → GitGuardian 실제값 40% 높음, 6.4% vs 4.6%).
- 출처 불명 매체는 인용하지 않는다. 글 끝에 **출처 섹션**(항목별 링크).

## 4. 차트 하우스 스타일 — 터미널/모노

- 다크 터미널 창: 신호등 점 3개 + 파일명 타이틀바 + monospace + `$` 프롬프트 + `#` 주석.
- 바는 유니코드 블록(`█` 채움 / `░` 빈칸), `letter-spacing:-.5~-1px`로 solid하게.
- 팔레트: **Tokyo Night** — bg `#1a1b26`, panel `#16161e`, line `#2a2e42`, text `#a9b1d6`, dim `#787c99`,
  comment `#565f89`, empty `#292e42`, 파랑 `#7aa2f7`, 초록(프롬프트/상승) `#9ece6a`, 주황(하락/경고) `#ff9e64`, 보라 `#bb9af7`. 히어로 타이틀만 밝게 `#c0caf5`.
- 차트 텍스트는 영어(터미널 관례) → ko/en 글이 같은 이미지 공유.
- **PNG는 터미널이 끝까지 꽉 차게**(바깥 프레임/여백 금지). 사이트의 `prose-img` 테두리·라운딩이 프레임 역할.
- **캔버스 폭은 콘텐츠에 맞춘다.** 터미널 텍스트는 왼쪽 정렬이라 캔버스가 넓으면 오른쪽에 검정 여백이 뜬다 → 콘텐츠(제목·바) 폭 + 패딩 정도로 좁혀서 꽉 차게(예: 히어로 860px, 도구 940px). 세로도 콘텐츠에 맞게 트림.
- **팔레트는 Tokyo Night로 확정**(2026-07-14, 사용자 선택: GitHub Dark·Dracula 후보 중). 위 §4 hex 그대로. 다른 테마로 스왑하려면 `scripts/blog-figures/term.css`의 `:root` 변수만 교체 후 재렌더.
- 소스: `scripts/blog-figures/` (term.css + t-*.html). 렌더: Chrome headless `--force-device-scale-factor=2` → `public/assets/`.
- generic "AI 대시보드" 느낌 금지 — 이 터미널 톤으로 통일.

## 5. 이중언어 인터랙션

- 글은 `src/data/<slug>.ts`에 문장 단위 `{ko,en}` 정렬(`type:'p'`의 `s:[]`).
- `BilingualArticle.astro` 컴포넌트: **문장 클릭 → 반대 언어 팝오버**(드래그 아님), 상단 토글로 주 언어 전환.
- 글은 `.mdx`로 컴포넌트 임베드. en 글은 같은 blocks 공유 + `lang="en"` + `translationKey`로 `/en/blog/` 연결.
- 마크다운 CJK 볼드 함정: 한글 조사에 바로 붙는 `**볼드**`는 안 먹음 → `<strong>` HTML 사용.
- 검증: 컴포넌트 `<script>`는 TS라 로컬 헤드리스 하니스로 볼 땐 타입 주석 다 벗겨야 파싱됨. 실제 빌드는 esbuild가 처리. 헤드리스 스크린샷은 `--virtual-time-budget`이 런타임 append 오버레이를 합성 안 하니 인터랙션 검증은 실렌더로.
